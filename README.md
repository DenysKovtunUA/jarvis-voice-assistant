# Jarvis Voice Assistant Engine (v3.1 Monolith)

[![HACS Badge](https://shields.io)](https://github.com)
[![HA Version](https://shields.io)](https://home-assistant.io)

Official lightweight custom conversation agent integration component for the **"Jarvis v3.1"** local voice ecosystem within Home Assistant.

This integration is specially optimized to run on the **Orange Pi 5 Pro (RK3588)** host platform, leveraging the hardware Neural Processing Unit (NPU), a custom localized LLM agent based on **Qwen 2.5 2B**, and a fuzzy entity matching engine (Levenshtein Distance Algorithm).

## 🚀 Architectural Features v3.1 (Monolith)

Unlike generic bloatware LLM integrations, this component completely strips away overhead functions that introduce latency and instability into the voice pipeline:
* **Total Determinism**: The integration hard-locks streaming to off (`stream: false`), eliminating the need for unstable token chunk parsing. This entirely prevents `aiohttp` internal client connection drops (TimeoutError 30s) and results in instant response times.
* **Sterile Environment**: The data transfer layout is fully stripped of incompatible encodings, preventing local LLM tokenizer degradation.
* **Direct Duplex Webhook**: The component binds the Home Assistant core pipeline to the local host Python daemon running on port `8090` using a single rapid POST request, sending raw text and expecting a flat payload response.

## 🛠️ Installation & Setup Guide

### Step 1: Add Custom Repository to HACS
1. Open your **Home Assistant** web interface and navigate to **HACS**.
2. Click on the **three vertical dots** in the top right corner and select **Custom repositories**.
3. In the **Repository** text field, paste your GitHub link:
   ```text
   https://github.com
   ```
4. In the **Type** dropdown menu, select **Integration** and click **Add**.
5. Find the newly appeared `Jarvis v3.1 Engine` card, click on it, and select **Download**.
6. Restart Home Assistant Core.

### Step 2: Activate Integration via UI
1. Go to **Settings** ➡️ **Devices & Services**.
2. Click the large blue **"Add Integration"** button in the bottom right corner.
3. Search for **`Jarvis v3.1 Engine`** and click it.
4. The component will instantly register itself over the local loopback host interface (`http://127.0.0.1:8090`) and create a conversational agent entity without forcing any configuration popups.

### Step 3: Map Voice Assistant Pipeline
1. Go to **Settings** ➡️ **Voice Assistants**.
2. Select or create your active voice assistant profile (the pipeline mapped to your ESP satellites, e.g., `Jarvis System`).
3. In the **Conversation agent** dropdown list, select **`Jarvis v3.1 Engine`**.
4. Click **Save**.

## 📝 Backend Requirements (Local Host)
To handle incoming pipelines successfully, your local host network Python daemon (`voice_interface.py`) running on the Orange Pi bare metal or inside a docker container with `network_mode: "host"` must listen on port `8090` and return a flat JSON payload structure matching this model:

```json
{
  "output": "The text answer generated by Qwen, which will be passed to Piper TTS",
  "tool_calls": []
}
```
